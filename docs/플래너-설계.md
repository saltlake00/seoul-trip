# 일정 플래너 설계

> 상태: 설계 확정, 구현 전 (2026-10-14)
> 참고: [yeonsu-k/Travel_Scheduling_Planner](https://github.com/yeonsu-k/Travel_Scheduling_Planner) — MYRO 클론 팀 프로젝트(2023).
> **라이선스가 없는 저장소라 코드는 가져오지 않는다.** 화면 흐름(일정 만들기 → 편집)만 참고하고 코드는 새로 짠다.

## 1. 목적

지금은 `data/trip.js`를 손으로 고쳐 일정을 바꾼다. 플래너는 **화면에서 장소를 검색해 담고, 날짜별로 끌어 옮겨
일정을 짠 뒤 `trip.js`로 내보내는 편집 도구**다. 일행이 보는 페이지(`index.html`·`plan.html`)는 그대로 둔다.

## 2. 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 위치 | 이 저장소에 `planner.html` 추가 | 결과물이 곧 `trip.js`라 같은 곳에 두면 내보내기·확인이 한 번에 된다 |
| 범위 | 혼자 쓰기. 서버·회원·DB 없음 | 공유는 이미 GitHub Pages 일정 페이지가 한다 |
| 저장 | 브라우저(localStorage) 자동 저장 + `trip.js` 내보내기 | 서버 없이 끝난다 |
| 지도 표시 | 네이버 지도 JS API v3 | 사용자 요구 |
| 장소 검색 | 카카오 로컬(카카오맵 JS SDK `services` 라이브러리의 `Places`) | 도메인 제한 공개 키로 브라우저에서 바로 부를 수 있어 **프록시가 필요 없다**. 페이지당 15건 |
| 기술 | 빌드 없는 vanilla JS (기존 `app.js`와 같은 방식) | 저장소가 정적 사이트다. React·Vite를 들이면 배포 구조가 바뀐다 |
| 끌어 놓기 | SortableJS(cdnjs) — 목록 사이 이동은 `group` 옵션 | 참고 저장소의 react-beautiful-dnd는 React 전용이고 유지보수가 끝났다 |

검토하고 버린 안:
- **네이버 검색 API 지역검색**: 결과가 최대 5건이고 사진이 없다. Client Secret이 필요해 프록시 서버를 따로 둬야 한다.
- **NCP Geocoding으로 지역 → 좌표**: 지역은 지도를 옮겨 고르고, 검색은 지도 중심 근처로 하면 된다. 필요 없다.

## 3. 키

둘 다 **공개돼도 되는 키**다. 등록한 도메인에서만 동작한다. 그래서 `.env`나 프록시 없이 `config.js`에 넣어 커밋한다.
비밀 키(Client Secret, REST API 키)는 쓰지 않는다. 혹시 생겨도 이 저장소에는 넣지 않는다.

| 키 | 발급처 | 등록할 도메인 |
|---|---|---|
| 네이버 지도 Client ID | 네이버 클라우드 플랫폼 콘솔 → Maps → Application 등록(Dynamic Map 선택) | `http://localhost:8792`, `https://saltlake00.github.io` |
| 카카오 JavaScript 키 | 카카오 디벨로퍼스 → 내 애플리케이션 → 플랫폼 키, Web 사이트 도메인 | 같은 두 곳 |

- 네이버 지도 스크립트 파라미터 이름은 2025년 개편 뒤 발급한 키 기준 `ncpKeyId`로 알고 있다. **발급 화면의 예제 코드를 기준으로** 맞춘다.
- NCP는 Application을 등록할 때 결제 수단 등록을 요구할 수 있다(무료 사용량 안에서 쓴다).
- 카카오 앱에서 「카카오맵」 사용 설정을 켜야 하는 경우가 있다. 검색이 막히면 먼저 이 설정을 본다.

## 4. 화면

참고 저장소의 「만들기(create)」와 「편집(edit)」을 한 화면으로 합친다.

```
┌ 상단: 여행 제목 · 시작일 · 일수 ─────────── [trip.js 가져오기] [후보 가져오기] [trip.js 내보내기] ┐
├ 왼쪽: 검색 ─────────┬ 가운데: 네이버 지도 ─────────┬ 오른쪽: 일정 ─────────────┤
│ 검색어 [      ] 🔍  │ 일자별 번호 마커 + 동선 선   │ [1일차] [2일차] [보관함]  │
│ (지도 중심 근처)    │ 선택한 항목 강조              │ 카드: 시간·종류·이름·메모 │
│ 결과 카드 [담기]    │                               │ 끌어서 순서·날짜 이동     │
└─────────────────────┴───────────────────────────────┴───────────────────────────┘
```

휴대폰에서는 세 칸을 탭(검색 / 지도 / 일정)으로 바꾼다.

### 동작

1. **시작**: localStorage에 저장본이 있으면 불러온다. 없으면 `data/trip.js`(`window.TRIP`)를 불러온다.
2. **검색**: 카카오 `Places.keywordSearch(검색어, cb, { location: 지도 중심, sort: accuracy })`. 결과 카드에는 이름·분류·주소·카카오맵 링크를 보여 준다.
3. **담기**: 결과를 보관함에 넣는다. 카드를 끌어 일자 목록으로 옮긴다. 종류(`type`)는 카카오 분류(`category_group_code`)에서 추정한다. 음식점은 식당, 카페는 카페, 숙박은 숙소, 그 밖은 관광이다. 카드에서 고칠 수 있다.
4. **편집**: 카드를 누르면 시간·종류·메모·이동(`move.mode`, `min`)·상태(확정/후보)를 고친다. 이동 시간은 자동으로 계산하지 않는다. 길찾기 API는 서버가 필요하다.
5. **후보 가져오기**: `data/board.js`의 `candidates` 가운데 `status`가 `제외`가 아닌 항목을 `map` 검색어(없으면 `name`)로 카카오에서 찾는다. 첫 결과의 좌표를 붙여 보관함에 넣는다. 찾지 못한 항목은 좌표 없이 넣고 「좌표 없음」 표시를 한다.
6. **내보내기**: 현재 상태를 `trip.js` 전체 텍스트로 만든다. `days` 외의 필드(`meetup`·`stay`·`transport`·`pending`·`checklist` 등)와 파일 머리 주석은 불러온 값을 그대로 둔다. 다운로드하고 클립보드에도 복사한다. 저장소 반영은 사람이 파일을 덮어쓰고 커밋한다(갱신 가이드 4절 배포와 같다).
7. **보관함**은 내보내지 않는다. 플래너 저장본에만 남는다.

### 공개 범위

`planner.html`도 GitHub Pages에 같이 올라간다. 상단 메뉴에는 넣지 않는다. `noindex`는 둔다. 편집 결과는 각자 브라우저에만 남아서 다른 사람이 열어도 원본은 바뀌지 않는다.

## 5. 파일

| 파일 | 역할 |
|---|---|
| `planner.html` | 뼈대. 네이버 지도·카카오 SDK·SortableJS를 불러온다 |
| `planner.js` | 상태(`TRIP` 사본 + `keep`), 검색, 끌어 놓기, 지도 갱신, 저장·내보내기 |
| `planner.css` | 플래너 전용 배치. 색·글꼴은 `style.css` 변수를 그대로 쓴다 |
| `config.js` | 두 공개 키 |

## 6. 완료 확인 (실패할 수 있게 쓴 항목)

- [ ] `http://localhost:8792/planner.html`을 열면 콘솔 오류 없이 지도에 현재 `trip.js`의 1일차 마커 8개가 번호 순서로 뜬다
- [ ] 「국립중앙박물관」 검색 → 결과 첫 카드 좌표가 `trip.js` 값(37.52395, 126.98032)과 소수 셋째 자리까지 같다
- [ ] 검색 결과를 담아 2일차 3번째 자리로 끌어 놓으면 지도 2일차 동선 선이 그 순서로 다시 그려진다
- [ ] 1일차 카드를 2일차로 옮긴 뒤 새로고침해도 그대로다(localStorage)
- [ ] 아무것도 고치지 않고 내보낸 `trip.js`를 원본과 `days` 단위로 비교하면 차이가 없다(키 순서 제외)
- [ ] 후보 가져오기 후 보관함 수 = `board.js`에서 `제외`가 아닌 후보 수
- [ ] 폭 375px에서 가로 스크롤이 생기지 않고 탭 세 개로 바뀐다
- [ ] 키 없이 열면(빈 `config.js`) 지도·검색 칸에 「키 필요」 안내가 뜨고 편집·내보내기는 동작한다

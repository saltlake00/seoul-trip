# 안드로이드 앱 계획 (일정 알림 포함)

작성 2026-11-14 00:50. 여행이 **오늘(11/14) 12:18 용산역 집결**부터라 아침 출발 전에 폰에 설치되는 것이 끝 기준이다.

## 1. 목표와 범위

- 휴대폰에서 웹 페이지(`index.html`)보다 보기 편한 안드로이드 앱 하나. 사이드로딩(APK 직접 설치)만 한다. 플레이 스토어·iOS는 안 한다.
- **일정마다 알림.** 일정 시작 N분 전(기본 10분)에 「10분 뒤 · 괴담저장소 15:00~16:20 · 지하철로 이동」 같은 알림을 띄운다.
- 디자인을 앱답게 정리한다: 「지금/다음 일정」 카드, 일자 전환, 세로 타임라인, 지도 탭.
- 범위 밖: 준비 현황(`plan.html`) 화면 이식(웹 링크로만 연결), 일정 편집, 서버 푸시.

## 2. 지금 상태 (확인한 것)

  날짜는 `dates.start: "11월 14일(토)"` 같은 문자열뿐이라 **ISO 날짜가 없다** → 알림 시각을 못 만든다.
- 이 PC에 JDK·Android SDK가 없다(`java: command not found`, `%LOCALAPPDATA%\Android` 없음, Unity에도 Android 모듈 없음). Node 24, Codex CLI, gh는 있다.

## 3. 방식: Capacitor 7로 감싼 웹 앱

참고: Capacitor 공식 `@capacitor/local-notifications`(ionic-team/capacitor-plugins). 웹 기술 그대로라 기존 데이터·좌표·지도(Leaflet)를 다시 쓸 수 있고, 알림은 네이티브 AlarmManager로 예약돼 앱이 꺼져 있어도 뜬다.
PWA는 앱이 닫힌 상태에서 시각 예약 알림을 못 띄워서(Notification Triggers 미지원, 푸시는 서버 필요) 뺐다.

### 폴더

```
android-app/
  package.json          # @capacitor/core·cli·android·local-notifications 7.x, leaflet
  capacitor.config.json # appId kr.saltlake.seoultrip, webDir www
  scripts/copy-data.mjs # ../data/trip.js → www/data/trip.js, leaflet → www/vendor/
  www/
    index.html  app.css  app.js     # 앱 전용 화면 (웹 페이지와 별개)
    alarms.js                        # 알림 시각 계산(순수 함수) + 예약
  test/alarms.test.mjs              # node --test
  android/                          # npx cap add android 결과를 커밋 (매니페스트 수정 포함)
.github/workflows/android.yml      # APK 빌드
```

웹 페이지(`index.html`·`app.js`·`style.css`)는 건드리지 않는다. 바꾸는 공용 파일은 `data/trip.js` 하나(일자에 `date` 추가)뿐이다.

### 데이터

- `data/trip.js` 각 일자에 `date: "2026-11-14"` / `"2026-11-15"`를 더한다. 웹 `app.js`는 모르는 필드를 무시하므로 영향 없음(구현 때 grep으로 확인).
- 앱은 빌드 때 복사한 `trip.js`를 쓴다(오프라인 동작). **원격 새로고침은 하지 않는다**: 원격 JS를 앱에서 실행하는 것은 위험하고, 일정이 바뀌면 다시 빌드하는 편이 단순하다. 이태원 점심처럼 미정인 항목은 시각이 정해져 있으므로 알림에는 지장 없다.

## 4. 화면

- 상단: 제목·날짜, 오른쪽에 알림 설정 버튼(종 아이콘).
- **지금/다음 카드**: 현재 시각 기준 진행 중이거나 다음 일정. 「35분 뒤」 남은 시간, 장소, 이동 방법, 「카카오맵 길찾기」 버튼. 여행 전이면 「첫 일정까지」, 끝났으면 「여행 끝」.
- 일자 전환(1일차/2일차 세그먼트). 오늘 날짜면 그날이 기본.
- 세로 타임라인: 시각·종료 시각, 종류 칩(색), 이름, 메모, 이동 줄. 지난 일정은 흐리게, 진행 중은 강조. 항목마다 알림 켜기/끄기 토글.
- 하단 탭: 일정 / 지도(Leaflet, 번호 핀, 동선 선) / 정보(숙소·교통·준비물, 웹 준비 현황 링크).
- Pretendard 대신 시스템 글꼴(오프라인), 라이트·다크 둘 다. 화면 폭 360dp 기준.

## 5. 알림

- 시각 계산: `new Date(`${day.date}T${item.time}:00+09:00`)` − 선행 분. **KST를 문자열에 박아** 기기 시간대와 무관하게 한다.
- 선행 분 선택: 정시 / 5 / 10(기본) / 30분 전. `localStorage`에 저장.
- 예약 규칙: 이미 지난 시각은 건너뛴다. 끈 항목은 건너뛴다. 알림 id는 `day*100 + index`로 고정해 다시 예약할 때 `cancel` 후 `schedule`로 중복을 막는다. 앱 실행·설정 변경·토글마다 전체를 다시 예약한다.
- `schedule: { at, allowWhileIdle: true }`. 알림을 누르면 앱이 열리고 그 일정으로 스크롤(`localNotificationActionPerformed`의 `extra`).
- 권한: Android 13+ `POST_NOTIFICATIONS`는 첫 실행 때 `requestPermissions()`. 정확한 시각은 매니페스트에 `SCHEDULE_EXACT_ALARM`을 넣고, 실행 때 `checkExactNotificationSetting()`이 거부면 상단 배너와 「설정 열기」(`changeExactNotificationSetting()`) 버튼. 거부돼도 부정확 알림으로는 뜬다.
- 「10초 뒤 시험 알림」 버튼을 설정에 둔다. 설치 직후 이것으로 알림이 실제로 뜨는지 본다.
- 삼성 등 배터리 최적화로 늦어질 수 있다는 안내 한 줄을 설정 화면에 둔다.

## 6. 빌드와 설치

- **GitHub Actions**(ubuntu, Android SDK 기본 설치)로 빌드한다: `setup-java 21` → `npm ci` → `npm run copy` → `npx cap sync android` → `./gradlew assembleDebug` → APK를 artifact로 올린다. 로컬에 JDK·SDK(1~2GB)를 깔지 않는다.
- `gh run download`로 APK를 받아 위키 밖 `E:\GitHub\seoul-trip\android-app\dist\`(gitignore)에 둔다. 사용자가 카카오톡 「나와의 채팅」이나 USB로 폰에 옮겨 설치(출처를 알 수 없는 앱 허용).
- 디버그 키로 서명한다. CI가 실행마다 새 디버그 키를 만들어 **다시 빌드한 APK는 지우고 새로 설치**해야 한다(덮어쓰기 실패). 여행 이틀 동안이면 감수한다.
- CI가 실패하면 대안: `winget install Microsoft.OpenJDK.21` + Android cmdline-tools로 로컬 빌드.
- 저장소가 공개라 APK 자체를 커밋하거나 릴리스로 올리지 않는다(artifact는 90일 보관, 로그인 필요).
